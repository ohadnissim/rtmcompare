## 4 · Open items

These don't block ship but should be tracked for v5.2.x patches or v5.3:

1. **Visual sign-off on light theme** (#16). Code audit done; needs human visual check on all v2 surfaces under `data-theme="light"` once the user spins `npm run dev`. Likely tweaks: `--rtm-frame-border` opacity, `--rtm-overflow-shadow` darkness.
2. **Visual sign-off on v1 fallback** (#17). Code audit shows zero unintended v1 changes. Needs human walk-through of the manual checklist in `v5.2-fallback-notes.md`.
3. **`buildMetricCells` returns max 4 cells.** Surface "post" / "broadcast" specs may want LUFS-S or PLR cells too. Easy add when the data shape is confirmed.
4. **`TabVerdict` for `'match'` and `'quality'` reads `.eq_match_score` and `.quality_score` defensively** — these may not exist on every result shape. The `null` return path is the safety net. Confirm with `analyze.py` outputs.
5. **EmptyStateV2 omits the v1 educator banner, library shortcut, deep-scan toggle, profile picker.** This is intentional per the brief (cover is the cover). v5.3 follow-up: surface these via OverflowMenu sub-sections so v2 users don't lose access.
6. **OverflowMenu's "Keyboard shortcuts" row is hidden by default** — the `onOpenShortcuts` prop is unimplemented in App.tsx because `<ShortcutHelp />` doesn't expose an external open API. Either keep the `?` keypress as the only affordance, or refactor ShortcutHelp to accept an `openSignal` ref in v5.3.
7. **No verdict on the Atmos tab.** The brief deferred Atmos to v5.3; honoured.
