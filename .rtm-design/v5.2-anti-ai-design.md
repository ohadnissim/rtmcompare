# Anti-AI-Design Discipline — RTMcompare v5.2

> **The most important constraint in this entire build.**
> Read before opening any v5.2 file. Re-read during review.
> If a screenshot of the result could plausibly be a Lovable / v0 / Bolt / shadcn-template output, the work has failed — regardless of how clean the code is.

---

## Why this matters

RTMcompare is a tool for engineers at the top of their craft. Audio mastering is a discipline where the difference between competent and master-level is measured in dB and milliseconds. The visual surface has to telegraph that same standard before a single number is read. Software that *looks* AI-generated tells the user "this was made by a template, you are using a template." Master-level engineers don't use templates. They will close the app.

The Console Didone philosophy is the positive direction. This document is the negative space — the failure modes that even a careful AI agent (Claude included) drifts toward when not held.

---

## The hard NO list

These are mechanical rules. If any of them appear in v5.2 code, the change is wrong, full stop. No "but it looks nice with…", no "subtle exception."

### Visual surface

1. **No `bg-gradient-*`, no CSS gradients period.** Gradients are AI-design tell #1. Solid colours only. The single allowed exception is the right-edge fade on the overflow scroll state of the metric strip — and only because it serves overflow legibility, not aesthetic.
2. **No `backdrop-blur-*` except on the existing v1 header** (Kensington-mandated, already in `App.tsx:858`). No frosted cards. No glassy panels. No translucent overlays "for depth."
3. **No drop shadows on type.** Ever.
4. **No 3D / extruded / neumorphic / glassmorphic surfaces.** No raised buttons. No inset wells. No "soft UI."
5. **No neon glow, lens flare, or "AI shine" on any surface.** No bloom on accents.
6. **No `rounded-md`, `rounded-lg`, `rounded-xl`, `rounded-2xl`, `rounded-3xl`.** Two radii exist: `2px` (`--radius-card`) and `full` (`--radius-pill`). Anything in between is a generic AI-design tell.
7. **No skeuomorphic imagery** (textures, brushed metal, leather, paper photo backgrounds). The "paper" of Console Didone is conceptual, not literal.
8. **No emoji.** Anywhere in the UI. Even in placeholder copy. Even "for warmth."
9. **No AI-generated illustrations.** No stock photos. No abstract blob shapes. If imagery is needed, it is typographic.
10. **No floating action buttons.** No bottom-right pill button. No "+" that hovers.
11. **No "Powered by AI" badges, sparkle icons, or magic-wand glyphs.** RTMcompare's analysis is a result, not magic.

### Layout

12. **No centred-stack hero pages.** Headline + subhead + button stacked centre is the single most overused AI-design layout. Asymmetry is mandatory in every v5.2 surface that contains a "moment."
13. **No three-column "feature card" grids.** No four-card stat dashboards. No bento-grid for its own sake.
14. **No icon-with-label rows where the icon is decorative.** If an icon appears, it is functional (a chevron indicating expandable content, an arrow indicating direction). Icons are NEVER the focal element.
15. **No section headers shaped like "How it works" / "Why us" / "Features."** This is a desktop tool, not a landing page.

### Colour

16. **No three-colour "modern" palettes** — purple + pink + blue, teal + orange + indigo, lime + violet + magenta, any combination that signals "Lovable startup template." Only the existing sand / terra / sage / warm-red / warm-amber / teal / slate-blue tokens.
17. **No tailwind grays as accent text** (`text-zinc-400`, `text-slate-500`, `text-gray-300`). Only `--color-sand-*` for greys.
18. **No vibrant "primary" colour like `blue-500`, `indigo-600`, or `emerald-500`.** Gold (`--color-terra`) is the only accent and it appears once per surface.
19. **No "tinted" backgrounds** (`bg-blue-50/50`, `bg-purple-100/30`). Backgrounds are sand-* tokens at full opacity, or transparent.

### Typography

20. **No "Inter / Geist / SF Pro" alone.** The Instrument Serif / Outfit / JetBrains Mono trio is established and earned. Don't import another sans "for variety."
21. **No `font-bold` (700+) on body text.** Body weight is 400. Display weight is 400. The contrast between display serif and body sans does the heavy lifting; weight does not.
22. **No `text-2xl` headlines on landing-page-shaped sections.** Headlines either reach the operatic ratio (Didone hero) or stay quiet (h3 tracked-caps sand-300). Nothing in between for v5.2.
23. **No rotated, mirrored, or decorative text. No outlined letterforms. No type-as-icon.** All text is left-to-right, no transforms.
24. **No sentence-case button labels** ("Begin Analysis", "View Details"). Either tracked-caps ("BEGIN ANALYSIS") or italic display ("Begin analysis"), per context.
25. **No system-emoji in copy** ("Get started 🚀", "Made with ❤️"). The copy tone is direct, dignified, and never cute.

### Motion

26. **No animation-on-scroll, parallax, or scroll-triggered reveal.** RTMcompare is a desktop tool, not a marketing site.
27. **No Lottie animations.** No SVG path-draw animations. No looping marquees.
28. **No "spring" easing curves** that bounce. The only easing token is `--easing-shell: cubic-bezier(0.32, 0.72, 0, 1)` — slow-out, no overshoot.
29. **No more than the one sanctioned motion** in v5.2 (metric-strip stagger fade-in). Tooltip and overflow-menu transitions count as the second and third — that is the cap. No new motion without writing a brief amendment.

### Copy

30. **No "Get started in seconds." No "Try it now." No "Loved by 10,000+ engineers."** No marketing copy of any kind in the app surface.
31. **No "Welcome back, Ohad! ✨"** No personalised greeting. The empty state is a cover page, not a friendly assistant.
32. **No questions phrased as "What would you like to do today?"** Direct imperatives: "Drop two audio files to begin." Statements, not invitations.
33. **No "Loading…" with an ellipsis.** A quiet "Analysing" or progress strip, no dots dancing.
34. **No "Oops!" / "Something went wrong" / "Don't worry"** error copy. Errors state what failed and what to do next — in the tone of an engineer's notebook, not a chatbot.

### Component shapes

35. **No `Card` component with `rounded-2xl shadow-md p-6` boilerplate.** Containers are bespoke; if a panel needs framing, it gets a 1px border in `sand-700/12%` and a 2px radius — nothing else.
36. **No "Modal" overlay with backdrop-blur, scale-in animation, and a close × in the corner.** If a modal is needed in v5.2, it is a side-sheet from the right, no blur, no scale, just opacity 0 → 1 over `--duration-menu`.
37. **No "Toast" notifications** at the bottom-right or top-centre. Status changes are inline.
38. **No "Tabs" component with rounded pills and a sliding underline.** The current tab nav (1px gold underline on active, sand-300 inactive) is correct; do not "modernise" it.
39. **No "Banner" component with a coloured background, an icon, and a dismiss ×.** If a notice is needed, it's a single line of italic display in `sand-300` italics, with a small terra dot if it's an alert.

## Red flags during review

If you catch yourself or another agent suggesting any of the following, stop and re-read the philosophy:

- "We could add a subtle gradient here for depth."
- "Let's lift this card with a soft shadow."
- "Adding a Lucide icon next to each metric makes it scannable."
- "The hero would benefit from an illustration."
- "Maybe a teal-to-purple gradient on the active state?"
- "Centred works better here for emphasis."
- "Should we add a 'Powered by RTM AI' line?"
- "Lottie animation for the loading state would feel premium."
- "Skeleton loaders matching the card shape."
- "Let's use Geist instead — Outfit feels dated."
- "A subtle blur on the modal backdrop adds focus."
- "We should add a primary CTA button on the empty state."
- "Confetti when analysis completes."
- "What if the verdict number had a subtle glow when violation?"
- "Let's reduce the wordmark size — 30px feels heavy."

Every one of those suggestions is the AI-design template trying to seep in. The correct response is no.

## Positive direction (what we are aiming at)

Re-read these references when in doubt:

- **Vogue Italia** covers — single monumental statement on a black field.
- **Monocle** quarterly layouts — generous space, refined sans + display serif pairing, numeric work treated as language.
- **Bottega Veneta** wordmark-only campaigns — restraint as the loudest statement.
- **Peter Saville** at Factory Records — typographic confidence, asymmetric rigor.
- **Massimo Vignelli** — numeric typography, registration marks, colophon vocabulary.
- **Bruno Monguzzi** monographs — measured, dense, every glyph earned.
- **Stanley & Silke** book jackets — black, cream, gold, italic display serif, asymmetric.

What these share, and what RTMcompare must share:
- One strong move per composition.
- Negative space as a material.
- Numbers and letters as proper names.
- A single chromatic gesture, used once.
- Asymmetry that breathes.
- A weakness — one intentional imperfection — that signals a human hand.

---

## The acceptance test

Before any v5.2 commit ships:

1. Take a screenshot of the result.
2. Ask: *Could this screenshot plausibly be the output of v0, Lovable, Bolt, or a shadcn template?*
3. If yes — even slightly — the work fails. Revise.
4. If no, and the screenshot reads as if a designer with twenty years in editorial publishing and twenty years in mastering had hand-built it — ship.

This is the only review criterion that matters more than the other 38 rules combined.
